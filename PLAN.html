Expense Tracker 💰

Scope, data model, and implementation plan.

Companion document: a formatted version of this plan is available as docs/Expense-Tracker-Project-Overview.docx for sharing.

1. Objective

"A browser-based application that records daily expenses and displays a running total."

2. Scope

2.1 In scope — Version 1

1Add expenseCapture a description and an amount from the user
2Display listRender all recorded expenses on the page
3Automatic totalRecalculate and display the sum on every change
4Delete expenseRemove an individual entry and update the total
5ValidationReject empty or non-numeric input with an on-screen message

2.2 Deferred — enhancement backlog

—CategoriesFood / travel / bills, with category filtering
—PersistenceRetain data across sessions via localStorage
—DatesDate per entry, with monthly views
—ReportingHighest expense, spending trends
Scope discipline: eight candidate features were identified; five were selected for Version 1 and the rest deferred. A small application that works end to end is more valuable than a large one left unfinished.

4. Data Model

A single expense is an object; the collection is an array of such objects.

// A single expense
{ item: "Tea", amount: 50 }

// The full collection
const expenses = [
  { item: "Tea",       amount: 50 },
  { item: "Taxi",      amount: 120 },
  { item: "Groceries", amount: 200 }
];

4.1 Operations

Feature Implementation approach
Add expense Append a new object to the array, then re-render
Display list Iterate the array, creating one element per entry
Calculate total Accumulate the amount property across entries
Delete expense Remove the entry and its element, then recalculate
Known constraint: an input element's value property always returns a string. The amount must be converted with Number() before any arithmetic, otherwise the + operator performs string concatenation instead of addition.

5. Technology

📄index.htmlDocument structure and element identifiers
🎨style.cssPresentation layer
⚙️app.jsApplication logic and event handling

No frameworks or third-party libraries. No build step, server, or database required.

6. Implementation Plan

1StructureComplete HTML with all identifiers — no scripting
2AddCapture input and append an entry to the list
3TotalCalculate and display the running total
4DeletePer-entry removal with total recalculation
5ValidationReject invalid input with a visible message
6StylingLayout and visual polish
Each phase is verified in the browser before the next begins. A phase is complete only when its feature works end to end.

7. Test Cases

  1. A valid expense is added and appears in the list.
  2. The total equals the arithmetic sum of all listed amounts.
  3. An empty description or amount is rejected with a visible message.
  4. A non-numeric amount does not corrupt the total.
  5. Deleting one entry removes only that entry and updates the total.
  6. Deleting all entries returns the total to zero.
